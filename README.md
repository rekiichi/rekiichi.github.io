# れきいち — テスト範囲で解ける歴史一問一答

教科書と定期テストの範囲（章・節）を選ぶと、その範囲だけの一問一答を作れる、高校生向けの歴史学習サイトです。歴史総合・世界史探究・日本史探究に対応しています。[Astro](https://astro.build/) で静的サイトとして書き出し、GitHub Pages で公開します。

> **はじめて公開する人は、まず [公開までの手順.md](公開までの手順.md) を読んでください**（GitHub と Google AdSense に登録するだけで公開できるように、順番に書いてあります）。この README は、中身を直したい人向けのくわしい説明です。

> サイト名「れきいち」は `src/site.config.ts` の `name` で変更できます（OGP 画像は「[OGP 画像の作り直し](#ogp-画像の作り直し)」を参照）。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| テスト範囲パッケージ | 科目 → 教科書 → 範囲（章・節にチェック、または「第◯章〜第◯章」）で問題セットを作る。出題数・出題順（教科書順／ランダム）・重要度（基本／標準／発展）・「苦手だけ」で絞り込み。範囲は URL に入るので友達と共有でき、「マイ範囲」に保存もできる |
| 出題画面 | 「答えを見る → ○×で自己採点」と「入力して判定」の2つの答え方。入力モードは全角・半角、ひらがな・カタカナ、中黒やスペースの有無、漢数字、別解などを許容。進捗と正答率を表示し、まちがえた問題を記録 |
| 章ページ | 章ごとに問題と答えを静的 HTML で一覧表示（答えは赤シートのようにタップで表示）。「この章で練習する」ボタン |
| 受験復習モード | 縦割り（世界史・歴史総合は地域別、日本史はテーマ別。年代順）と横割り（世紀・時代別。同じ時代の各地域をまとめる）。それぞれ専用ページを生成 |
| テスト直前モード | 重要度「基本」の問題だけを、ランダムにすばやく回す |

ログイン機能はなく、学習記録・マイ範囲・設定はブラウザの localStorage にだけ保存します（個人情報は集めません）。

## ローカルでの確認方法

必要なもの: **Node.js 22.23.4 以上**（推奨は 24。`.nvmrc` に記載）と npm。

```bash
npm install
```

```bash
npm run dev
```

ブラウザで http://localhost:4321/ を開きます。起動前に CSV → JSON の変換とデータの検証が自動で行われます（検証でエラーがあると起動しません。表示されたファイル名・行番号を見て直してください）。

本番と同じ形で確かめるときは、ビルドしてからプレビューします。

```bash
npm run build
```

```bash
npm run preview
```

## 問題の追加方法（CSV の書式）

1. スプレッドシート（Google スプレッドシート・Excel など）で、1行に1問ずつ書きます。
2. CSV で書き出し、`data/questions/` に置きます（ファイル名は自由。例: `sekaishi-tankyu.csv`）。
   - Google スプレッドシート: ファイル → ダウンロード → カンマ区切り形式（.csv）
   - Excel: 「CSV UTF-8（コンマ区切り）」で保存（ふつうの「CSV」＝ Shift_JIS も読めますが、UTF-8 をおすすめします）
3. `npm run data`（または `npm run dev` / `npm run build`）を実行すると、同じ名前の JSON（例: `sekaishi-tankyu.json`）が作られ、検証されます。
4. 問題を教科書の節に割り当てます（[教科書データの追加方法](#教科書データの追加方法)）。

### 列（1行目の見出し）

| 見出し | 英語の見出し | 必須 | 内容 |
| --- | --- | --- | --- |
| ID | `id` | ○ | 問題ID。半角英数字・ハイフン・アンダースコア（64文字まで）。サイト全体で重複不可 |
| 科目 | `subject` | ○ | `歴史総合`・`世界史探究`・`日本史探究`（短い名前 `世界史` や科目IDでも可） |
| 問題文 | `question` | ○ | |
| 答え | `answer` | ○ | 正解の表記 |
| 読み | `reading` | | 答えの読みがな（ひらがな）。答えを表示したときに出る。入力モードの判定には使わない（漢字の答えは漢字で書く） |
| 別解 | `alternatives` | | 正解として扱うほかの表記。複数は `\|` で区切る（例: `元寇\|文永・弘安の役`） |
| 解説 | `explanation` | | 短い解説（目安120字以内。超えると警告） |
| 開始年 | `year_start` | | 年代。紀元前は `前221` か `-221`（`1789年` も可）。`1800ごろ` と書くと「1800年ごろ」と表示する。先史時代は `約700万年前` のように書ける |
| 終了年 | `year_end` | | 期間がある場合だけ（例: 1914〜1918 の 1918） |
| 地域 | `regions` | | 地域タグ。複数は `\|` か `、` で区切る。**主な地域を先頭に** |
| テーマ | `themes` | | テーマタグ（政治・外交・経済・社会・宗教・文化）。複数は `\|` か `、`。**主なテーマを先頭に** |
| 重要度 | `level` | ○ | `基本`・`標準`・`発展`（`1`〜`3` や `basic` なども可） |
| 確認済み | `verified` | | `TRUE` のときだけサイトに出る（`○`・`1`・`済` も可）。**空欄や `FALSE` は未確認＝公開しない** |
| メモ | `memo` | | 作成者用のメモ（出典など）。サイトには出ません |

- 見出しの順番は自由です。知らない見出しの列は無視されます（警告が出ます）。
- 空の行は無視されます。
- 例:

```csv
ID,科目,問題文,答え,別解,解説,開始年,終了年,地域,テーマ,重要度,確認済み,メモ
w-0001,世界史探究,前221年に中国を統一し、初めて「皇帝」の称号を用いた秦の王は？,始皇帝,秦の始皇帝,郡県制を全国に広げた。,前221,前210,中国,政治,基本,TRUE,出典などのメモ
w-0002,世界史探究,1789年、バスティーユ牢獄の襲撃から本格化した革命は？,フランス革命,,同年に人権宣言が出された。,1789,1799,ヨーロッパ,政治,基本,FALSE,要確認
```

### 問題ID の付け方（おすすめ）

- 収録済みの問題は `<科目の頭文字>-<章2けた><節2けた>-<連番2けた>` です（例: `w-0102-03` = 詳説世界史 第1章 第2節の3問目。世界史 `w`、日本史 `j`、歴史総合 `r`）。問題を足すときは、その節の最後の番号の続きを使います（途中に入れて番号をずらさない）。
- 出題画面は ID の順で問題データを分割して読み込むので、教科書の順に番号を振ると少し速くなります。
- **一度公開した ID は変えないでください。** 学習記録（苦手）や共有された URL は ID に結びついています。問題をやめるときは「確認済み」を外します。
- `sample-` で始まる ID は開発用サンプルとして扱われます。

### 収録済みの問題

| 科目 | ファイル | 問題数 | 対応する教科書 |
| --- | --- | --- | --- |
| 世界史探究 | `data/questions/sekaishi-00.csv`〜`sekaishi-19.csv`（章ごと） | 1,905問 | 詳説世界史 |
| 日本史探究 | `data/questions/nihonshi-01.csv`〜`nihonshi-18.csv`（章ごと） | 1,474問 | 詳説日本史 |
| 歴史総合 | `data/questions/rekishi-sogo-01.csv`〜`rekishi-sogo-03.csv`（部ごと） | 432問 | わたしたちの歴史 |

- 問題・答え・読み・解説・年代・タグは、生成AI（Claude）が、高校の歴史で一般に学ぶ内容をもとに作成しました。教科書の本文は参照していません（節への割り当ては、目次の見出しとページ数から決めています）。
- 作成後に、年代の食い違い（問題文と年の欄、同じ用語どうし）、読みがな、同じ答えの重複、問題文に答えが入っていないか、を点検しています。それでも誤りが残っている可能性があるので、運営者情報のページにその旨を書き、誤りの報告を受けつけています。**報告を受けたら、CSV の該当する行を直して push してください**（ID は変えない）。
- 重要度は、基本が約6割・標準が約4割・発展は少数です。

### 地域・テーマのタグ

使えるタグは `data/taxonomy.json` にあります（地域: 日本・朝鮮・中国・内陸アジア・東南アジア・南アジア・西アジア・アフリカ・ヨーロッパ・ロシア・南北アメリカ・オセアニア・国際、テーマ: 政治・外交・経済・社会・宗教・文化）。タグを増やすときは `slug`（URL に使う半角英小文字）と `name`（CSV に書く名前）を追加します。

- **縦割り**（世界史探究・歴史総合は地域、日本史探究はテーマ）: タグごとにまとめ、年代順に並べます。複数のタグがある問題はそれぞれのまとまりに入ります。
- **横割り**: 開始年で時代区分（`data/subjects.json` の `periods`）に振り分け、時代の中は**先頭のタグ**でまとめます。
- 開始年がない問題は横割りに、軸のタグがない問題は縦割りに出ません（検証で警告が出ます）。

### JSON で直接書く場合

`data/questions/` に `{ "questions": [ ... ] }` の形の JSON を置いても読み込まれます（形は生成された JSON と同じ）。CSV から生成された JSON（`"generatedFrom"` があるもの）は、次の変換で上書きされるので直接編集しないでください。

## 教科書データの追加方法

教科書1冊につき1ファイルです。教科書には「章・節の番号と見出し」と「各節に対応する問題IDの一覧」を書きます。同じ問題IDを複数の教科書に書けば、1つの問題を複数の教科書で使えます。

### CSV で書く（おすすめ）

`data/textbooks/<教科書ID>.csv` を作ります（例: `data/textbooks/my-sekaishi.csv`）。`npm run data` で同じ名前の JSON が作られます。

| 見出し | 英語の見出し | 必須 | 内容 |
| --- | --- | --- | --- |
| 教科書ID | `textbook_id` | | URL に使う ID（半角英小文字・数字・ハイフン）。省略するとファイル名になる |
| 科目 | `subject` | ○ | `世界史探究` など |
| 教科書名 | `name` | ○ | 表示名（サイトでは「教科書名 第3章 一問一答」のように使われます） |
| 出版社 | `publisher` | | |
| 説明 | `description` | | 教科書ページに表示 |
| 並び順 | `order` | | 科目ページでの並び順（小さい順） |
| 出典 | `source` | | 章立て・ページを入力した元の資料（例: 出版社のウェブサイトの資料名と時期）。教科書ページの下に「〜をもとにしています」と表示 |
| 部 | `part` | | 「第1部 原始・古代」などの上位の区分（章の一覧に見出しとして出る） |
| 章番号 | `chapter` | ○ | 0以上の整数（`第3章` `序章` も可。序章は 0） |
| 章の表示名 | `chapter_label` | | 「第◯章」以外で表示したいとき（例: 終章） |
| 章見出し | `chapter_title` | ○ | |
| 節番号 | `section` | ○ | 章の中で0以上の整数 |
| 節の表示名 | `section_label` | | 「第◯節」以外で表示したいとき（例: `1`） |
| 節見出し | `section_title` | ○ | |
| ページ | `pages` | | 教科書のページ（例: `p.12〜21`）。範囲選びの目安として表示 |
| 問題ID | `question_ids` | ○ | その節の問題ID。1つのセルに空白・`\|`・`、` 区切りで複数書ける。`w-0102-*` のように最後を `*` にすると、その文字で始まるすべての問題（ID の順）になる |

書き方のルール:

- 教科書ID・科目・教科書名・出版社・説明・並び順・出典は、**最初の行だけ**書けば十分です。
- **章番号・節番号が空の行は、前の行と同じ章・節**として扱います。そのため「1行に1節（問題IDを並べる）」でも「1行に1問」でも書けます。章見出し・節見出しも、その章・節の最初の行だけで十分です。
- 章・節は教科書の順（番号の小さい順）に並べ、同じ章・節の行は続けて書きます。
- 例（1行に1節）:

```csv
教科書ID,科目,教科書名,出版社,説明,並び順,部,章番号,章見出し,節番号,節見出し,ページ,問題ID
my-sekaishi,世界史探究,（教科書名）,,,1,,1,（第1章の見出し）,1,（第1節の見出し）,p.12〜15,w-0001 w-0002 w-0003
,,,,,,,1,,2,（第2節の見出し）,p.16〜25,w-0004 w-0005
,,,,,,,2,（第2章の見出し）,1,（第1節の見出し）,p.60〜63,w-0040
```

- 例（1行に1問）: `data/textbooks/sample-sekaishi-tankyu-b.csv` を見てください。

> 上の例の（　）の部分は、お手元の教科書に合わせて入力してください。

### 入力済みの教科書

| ファイル | 教科書 | 科目 |
| --- | --- | --- |
| `data/textbooks/watashitachi-no-rekishi.csv` | わたしたちの歴史（山川出版社） | 歴史総合 |
| `data/textbooks/shosetsu-sekaishi.csv` | 詳説世界史（山川出版社） | 世界史探究 |
| `data/textbooks/shosetsu-nihonshi.csv` | 詳説日本史（山川出版社） | 日本史探究 |

- 章・節の見出しと開始ページは、山川出版社ウェブサイトの内容解説資料「目次と配当時間例」（2026年10月時点）から入力しました（`出典` の列）。改訂で目次やページが変わることがあるので、お使いの教科書の版（教科書番号）と照らし合わせてください。
- 終わりのページは「次の項目の開始ページ − 1」です。部の扉のページ数が資料からわからない境目（詳説日本史の第4章第3節・第7章第4節・第10章第4節）は、`p.69〜` のように終わりを書いていません。
- 入れたのは、本文の章・節（テーマ）だけです。「第◯部を学ぶ前に」「第◯部まとめ」「歴史資料と◯◯の展望」「考えてみよう！」「◯◯への問い」「いまの私たちにつながる課題」「地球世界の課題の探究」「現代日本の課題の探究」、巻頭資料（地図）、年表・索引は入れていません。必要なら行を足してください。
- 「世界史へのまなざし」（詳説世界史）は、章番号 0・章の表示名「巻頭」で、①だけを入れています。②と、「歴史の扉」（わたしたちの歴史）は、探究活動のページなので入れていません。
- わたしたちの歴史は「部」と番号つきのテーマでできているので、部を章（表示名「第1部」など）、テーマを節（表示名はテーマ番号）にしています。範囲は「第1部の3・4」のように表示されます。
- 各節の `問題ID` は、`w-0102-*` のように「その節の問題すべて」を指す書き方にしています。問題の CSV に行を足せば、教科書の CSV を直さなくても、その節に入ります。
- この3つの CSV は、資料の目次から機械的に作りました。目次が改訂されたときは、行（章番号・節番号）を増やすのはかまいませんが、**すでにある章番号・節番号は変えないでください**（共有された URL やマイ範囲がずれます）。

`data/textbooks/<教科書ID>.json` に次の形で書きます。

{

  "order": 1,
  "chapters": [

### 教科書を追加したあと

- 科目ページに教科書が並び、教科書ページ・章ページ（問題が1問以上ある章だけ）が自動で作られます。問題がない章・節は「準備中」と表示されます。
- 未確認の問題・存在しない問題IDは公開されません（存在しない ID は検証エラー、未確認は警告）。
- 教科書ID・章番号は URL になるので、公開後は変えないでください。
- 教科書名は対応範囲を示すためだけに使います（全ページのフッターに注意書きが出ます）。

## サンプルデータについて

開発とテストのために、各科目のサンプル教科書（世界史探究は構成の違う2冊）と、各科目13〜14問のサンプル問題（うち各1問は「未確認」の例）が入っています。ファイル名と ID が `sample-` で始まります。内容は、実在の教科書とは関係ありません。

**公開するサイトには出ません**（`src/site.config.ts` の `includeSampleData` が `false`）。開発中にサンプルも見たいときは、環境変数を付けて起動します。

```bash
INCLUDE_SAMPLE_DATA=true npm run dev
```

サンプルのファイルは、自動テスト（`tests/`）が使っているので、消さないでください。

## データの検証

`npm run validate` はビルド前（`npm run build` / `npm run dev`）に自動で実行されます。**エラー**があるとビルドが止まり、**警告**は表示だけです。

| 種類 | 主な内容 |
| --- | --- |
| エラー | 問題IDの重複（ファイルをまたいでも）、教科書が参照している問題IDが存在しない、必須項目（ID・科目・問題文・答え・重要度）の抜け、ID の書式、知らない科目・タグ、年代の誤り（整数でない・終了年が開始年より前）、教科書IDの重複・書式、章・節の番号の重複や順番の誤り、同じ節に同じ問題が2回、時代区分の重なり |
| 警告 | 未確認の問題を参照している（公開されない）、公開される問題がない節、開始年・タグがなく受験復習モードに出ない問題、どの教科書にも載っていない問題、解説が長い、問題文に答えがそのまま含まれている、同じ問題文の重複、別の科目の問題を参照している |

CSV の書式の誤り（読めない年・使えない重要度など）は、変換のときに「ファイル名:行番号」つきで表示されます。

## GitHub Pages での公開手順

1. GitHub で新しいリポジトリを作ります。**リポジトリ名を `<ユーザー名>.github.io` にする**と、サイトが `https://<ユーザー名>.github.io/` の直下で公開され、robots.txt と ads.txt も正しい場所に置かれます（おすすめ）。ほかの名前（例: `rekishi-ichimon`）にすると、`https://<ユーザー名>.github.io/rekishi-ichimon/` で公開されます。公開・非公開どちらでも可（非公開リポジトリの GitHub Pages は有料プランが必要です）。
2. このフォルダを push します。

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "最初のコミット"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
```

```bash
git push -u origin main
```

3. GitHub のリポジトリで **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にします。
4. **Actions** タブで「Deploy to GitHub Pages」を開き、失敗していたら「Re-run all jobs」を押します（Source を設定する前の最初の実行は失敗することがあります）。
5. 成功すると `https://<ユーザー名>.github.io/`（リポジトリ名が `<ユーザー名>.github.io` のとき）または `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。以後は **main に push するたびに自動で公開**されます。

### リポジトリ変数（コードを直さずに設定する）

お問い合わせフォームの URL や AdSense の ID は、GitHub の **Settings → Secrets and variables → Actions → Variables タブ → New repository variable** で入れます。入れたあと、Actions の「Deploy to GitHub Pages」を **Run workflow** でもう一度実行すると反映されます。入れていない変数は、何も表示されないだけです。

| 変数名 | 入れる値 | 入れるとどうなるか |
| --- | --- | --- |
| `CONTACT_FORM_URL` | お問い合わせ用 Google フォームの URL（`https://…`） | お問い合わせページにフォームへのボタンが出る（空の間は「準備中」） |
| `REPORT_FORM_URL` | 誤り報告用の URL（任意）。Google フォームの「事前入力した URL を取得」で作り、問題ID の欄の値を `{id}` にする | 出題画面の「この問題の誤りを報告」が、問題ID入りでフォームを開く（空ならお問い合わせページへ） |
| `ADSENSE_CLIENT` | AdSense のパブリッシャー ID（`ca-pub-` で始まる16けたの数字） | 全ページに AdSense のコードと確認用のタグが入り、`ads.txt` が作られる |
| `ADSENSE_SLOT` | AdSense で作った広告ユニットの ID（数字） | 各ページの広告の位置に、広告が表示される |
| `GOOGLE_SITE_VERIFICATION` | Search Console の「HTML タグ」の `content` の値 | サイトの所有権の確認用のタグが入る |
| `OPERATOR_NAME` | 運営者情報に出す名前（ハンドルネーム可） | 運営者情報の「運営者」が変わる |

同じ項目は `src/site.config.ts` に直接書くこともできます（変数があれば変数が優先）。形式がまちがっている値（`ca-pub-` で始まらない ID など）は、ビルドがエラーで止まって教えてくれます。

- ベースパス（`/rekishi-ichimon`）やドメインは、ワークフロー（`.github/workflows/deploy.yml`）が自動で設定します。
- 公開前に、データの検証・テスト・型チェック・ビルド結果の確認が行われます。どれかが失敗すると公開されず、いまのサイトがそのまま残ります。失敗したら Actions のログを見てください（データのエラーはファイル名と内容が出ます）。
- CSV を GitHub の画面で直接編集・アップロードしても、公開時に JSON が作り直されます（リポジトリの JSON を更新したいときは、手元で `npm run data:csv` を実行してコミットします）。
- プルリクエストでは `.github/workflows/ci.yml` が同じ確認を行います（公開はしません）。

## 独自ドメインの設定手順

1. ドメインを取得します（例: `example.com`）。
2. （推奨）ドメインの乗っ取りを防ぐため、GitHub の **アカウントの Settings → Pages → Add a domain** でドメインを確認（verify）します。表示された TXT レコードを DNS に追加します。
3. DNS にレコードを追加します。
   - `www.example.com` のようなサブドメイン: **CNAME** レコードで `<ユーザー名>.github.io` を指定
   - `example.com`（ルート）: **A** レコードで `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`（IPv6 も使うなら **AAAA** で `2606:50c0:8000::153`、`2606:50c0:8001::153`、`2606:50c0:8002::153`、`2606:50c0:8003::153`）
   - 最新の値は GitHub のドキュメント「[GitHub Pages サイトのカスタムドメインを管理する](https://docs.github.com/ja/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)」で確認してください。
4. リポジトリの **Settings → Pages → Custom domain** にドメインを入れて **Save** します。DNS の確認が終わったら **Enforce HTTPS** にチェックを入れます（証明書の発行に少し時間がかかります）。
5. Actions で「Deploy to GitHub Pages」をもう一度実行します（または何か push します）。公開URL（`SITE_URL`）とベースパス（`BASE_PATH` が空になる）は自動で切り替わり、canonical・OGP・sitemap.xml・robots.txt も新しいドメインになります。GitHub Actions で公開する場合、`CNAME` ファイルは不要です。
6. [Google Search Console](https://search.google.com/search-console) にサイトを登録し、`https://example.com/sitemap.xml` を送信します。

> `https://<ユーザー名>.github.io/<リポジトリ名>/` のままだと、robots.txt がドメインの直下に置けないため検索エンジンに読まれません（サイトマップは Search Console から送信できます）。また AdSense の ads.txt もドメイン直下に必要なので、広告を出すなら独自ドメインをおすすめします。

## ほかの静的ホスティングに移す場合

`dist/` をそのまま置けるホスティング（Cloudflare Pages・Netlify・Vercel など）で動きます。

| 設定 | 値 |
| --- | --- |
| ビルドコマンド | `npm run build` |
| 公開ディレクトリ | `dist` |
| Node.js | 24（`.nvmrc`） |
| 環境変数 | `SITE_URL=https://example.com`（サイトの URL）。サブディレクトリで公開するときだけ `BASE_PATH=/サブディレクトリ名` |

ページは `/<パス>/index.html` の形で書き出されます。404 ページは `dist/404.html` です。

## Google AdSense を入れるとき

コードを書きかえる必要はありません。[リポジトリ変数](#リポジトリ変数コードを直さずに設定する)を入れるだけです。

1. AdSense に申しこみ、サイトの URL を登録します（AdSense の利用は18歳以上。18歳未満の人は、保護者が保護者自身の Google アカウントで申しこみます）。
2. AdSense の画面に出るパブリッシャー ID（`ca-pub-…`）を、リポジトリ変数 `ADSENSE_CLIENT` に入れて、もう一度公開します。これで、全ページの `<head>` に AdSense のコードと `google-adsense-account` のタグが入り、`ads.txt` も作られます。AdSense の「サイトの所有権の確認」は、「AdSense コード スニペット」か「メタタグ」を選べば通ります。
3. 審査に通ったら、AdSense で「ディスプレイ広告」の広告ユニットを1つ作り、その ID（`data-ad-slot` の数字）をリポジトリ変数 `ADSENSE_SLOT` に入れて、もう一度公開します。各ページの決まった位置に広告が出ます。

- 広告の位置は `src/components/AdSlot.astro` で決めています。ボタン・チェックボックス・○×ボタンのすぐ近くを避け、見出しや本文のまとまりの間だけに置いています。出題中の画面には出さず、出題画面は結果の下だけです。位置の一覧は次のコマンドで確認できます。

```bash
grep -rn "AdSlot name" src
```

- **AdSense の「自動広告」はオフのままにしてください。** 自動広告は、ボタンの近くにも広告を入れることがあり、押しまちがいの原因になります。
- `ads.txt` は、ドメインの直下（`https://ドメイン/ads.txt`）にあるときだけ有効です。リポジトリ名を `<ユーザー名>.github.io` にするか、独自ドメインを使ってください。`<ユーザー名>.github.io` の形の URL で審査に通るかどうかは、AdSense 側の判断によります。通らないときは、独自ドメイン（[独自ドメインの設定手順](#独自ドメインの設定手順)）を用意するのが確実です。
- プライバシーポリシー（`/privacy/`）には、広告配信・Cookie・localStorage の利用について記載済みです（広告を入れると「利用しています」という表現に自動でかわります）。

## サイトの設定

`src/site.config.ts` で変更します。

| 項目 | 内容 |
| --- | --- |
| `name` / `tagline` / `description` | サイト名・キャッチコピー・トップページなどの説明文 |
| `operatorName` | 運営者情報ページに出す名前（ハンドルネーム可） |
| `launchedOn` / `policyDate` | 開設時期・プライバシーポリシーの制定日 |
| `contactFormUrl` | お問い合わせ用 Google フォームの URL（空の間は「準備中」と表示）。リポジトリ変数 `CONTACT_FORM_URL` でも設定できる |
| `reportFormUrl` | 問題の誤り報告用 URL（任意）。Google フォームの「事前入力した URL を取得」で作った URL の、問題ID欄の値を `{id}` にして貼ると、出題画面の「この問題の誤りを報告」から問題ID入りで開きます。空ならお問い合わせページへ |
| `adsenseClient` / `adsenseSlot` / `googleSiteVerification` | AdSense と Search Console の設定。ふつうは[リポジトリ変数](#リポジトリ変数コードを直さずに設定する)で入れる |
| `includeSampleData` | 開発用のサンプルデータを含めるか（公開するサイトでは `false`） |
| `ogImage` | OGP 画像（`public/` からのパス） |

記事は `src/content/articles/*.md` に Markdown で書きます（いまは3本入っています）。先頭の `draft: true` の間は下書きで、検索結果に出ません。
